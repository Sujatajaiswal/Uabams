Gateway Upload Flow

Gateway creates a closed session folder, compresses it as a ZIP archive, and uploads it with HTTP PUT to /api/v1/archive.

Upload Endpoint PUT /api/v1/archive
Archive Name <gatewayId>__<trainId>__<sessionName>.zip
Metadata session_metadata.json
Database MongoDB Atlas Cloud Storage

Cloud Data Contract

This cloud service receives complete gateway session archives, validates and parses the files, stores both raw and processed data, and returns HTTP status responses to the gateway.

Server Receives HTTP PUT /api/v1/archive with raw ZIP bytes named <gatewayId>__<trainId>__<sessionName>.zip, plus optional POST /api/v1/alerts JSON alert events.
Server Processes session_metadata.json, rms/rms_25cm.bin, peak/peak_50m.bin, faults/faults.bin, and raw/*.bin files. RMS is parsed per about 25 cm segment; peak records are parsed per 50 m window.
Server Stores Original ZIP metadata, gateway payloads, extracted file metadata, RMS records, peak records, fault records, raw packet metadata, operation decisions, SMS logs, and alert events in MongoDB Atlas cloud storage.
Server Sends Back HTTP 201/200 after successful durable storage, HTTP 200 for duplicate archive, HTTP 422 for filename/metadata mismatch, and HTTP 4xx/5xx for upload or server errors.

Specification Alignment

Speed Band System data is intended for 20-160 kmph operation. Peak alert checks are speed-gated at 80 kmph.
Spatial Acceleration Data RMS spatial acceleration records are parsed from rms/rms_25cm.bin at about 25 cm intervals.
Processed Peak Data Peak records are parsed from peak/peak_50m.bin and summarized per 50 m window. If multiple peaks cross limits in the same window, the cloud keeps the highest vertical and highest lateral peak separately.
GPS Alert Location Safety alerts store measured peak value, speed, peak position, latitude, and longitude so the alert can be shown on the map and sent as notification data.
Route-wise Thresholds Vertical and lateral acceleration limits can be edited per route from 0 to 100g. Archive alert checks use the active route threshold where available.
Network/GSM Retry Model If GSM/network transfer is unavailable, the gateway keeps local session archives and retries later. Cloud returns 200/201 only after accepting the archive, so the gateway can safely clear local storage after confirmation.
TMS Handoff Cloud stores records in MongoDB Atlas and exports a TMS handoff package. The final transfer format can be ASCII/database export as agreed with the receiving TMS environment.

Measurement & Processing Requirements

Axle Box Range +/-100g
Bogie Range +/-5g
Frequency Range Axle 0-500 Hz | Bogie 0-100 Hz
Minimum Sampling Axle 2500 Hz | Bogie 500 Hz
Peak Location Accuracy < 5 m
Speed Accuracy +/-2%
Retention Raw 7 days | Spatial/alerts 30 days
System Scale Up to 100 train systems

Hardware measurement range, frequency response, sampling, environmental tests, GSM/private APN, and sensor mounting are gateway/hardware compliance points. The cloud stores the measured values, GPS/encoder location, speed, route-wise thresholds, alerts, and reports received from those systems.

TMS / MDB Handoff

The handoff package is generated from parsed archive/session records stored in MongoDB Atlas. It contains the two required TMS datasets and import instructions.
